# 筛选章程 · 闸门效率诊断

## 什么时候用

用户手上有一套**多条件筛选章程**（自有策略、或对标某个指数编制方案），并问出以下任一问题：

- "我的方法是不是多种条件叠加导致标的太少？"
- "哪一条最卡？"
- "这些条件是不是重复的？"
- "能改什么？"

**不适用**：用户只是想要一份筛选结果（那应该走筛选工具，不是诊断）。

## 核心诊断逻辑（四步）

一套 N 道闸的筛选章程，真正需要回答的是四个问题：

| 步骤 | 方法 | 回答什么 |
|---|---|---|
| 1 | **逐步漏斗回放** | 每道闸淘汰多少、在哪一步崩掉 |
| 2 | **留一法（Leave-One-Out）** | 单独放宽某道闸能多救回多少 → 量化**边际约束力**（脚本会把 `FINAL` 终局闸也一并测试——它常常是最大的那一关） |
| 3 | **Jaccard 冗余度矩阵** | 闸与闸筛出的集合重叠多少 → 区分"加保险"与"重复加码" |
| 4 | **候选质量对比** | 被挡住的那批 vs 通过的那批，质量谁更好 → 量化**代价方向** |

### 关键判读规则（这是本技能的核心价值）

1. **留一法增量 = 0 的闸是空转闸**。它在当期池子里不筛选任何东西。要检查它的通过率是否 100%；若是，其"避雷价值"只能靠历史记录证明，不能靠存在证明。

2. **Jaccard ≈ 通过率时是退化值**。若某闸通过率 100%（全通闸），它与其他闸的 Jaccard 退化为对方的通过率，**这不是冗余证据而是空转证据**。计算时要识别并剔除这一行，否则会误读。

3. **结合的效率是相关性的函数**：
   - 高相关因子（同族，Jaccard 高）→ AND = **加保险**，但边际避雷递减
   - 低相关因子（异族，Jaccard 低）→ AND = **换样本**，不是"同时得到"，是"用 A 换 B"
   - 这是回答"既要又要"问题的关键：**当两个条件在截面上重叠很低时，AND 的效果就是取交集 = 交换，而不是叠加安全边际。**

4. **候选质量对比暴露代价方向**。若被挡住那批在其它维度上**更优**，说明该闸不是"提高质量"，而是"用一个维度换另一个维度"。这是"既要又要"最有力的证据——要看**中位数**对比，不要看极值。

5. **兜底检查：先确认章程有没有"分段复核通道"**。成熟章程常用「硬阈值 + 分段复核」实现"合成得分"的等效效果。在做"改用合成得分"的建议前，务必先核对该标的在原章程里是否本来就能走复核通道被捞回来。**很多情况下结论会从"设计有问题"变为"设计对但没执行"。**

## 执行

```bash
python scripts/funnel_diagnose.py <csv_path> [--config gate_config.py]
```

脚本约定：

- CSV 首行为表头，取数列形如 `="1.234"` 或 `=1.234`（数据导出常见格式），脚本内置清洗。
- 闸门以 Python 函数定义，见 `--config` 指向的配置文件；不传则用内置的 `EXAMPLE` 作模板。
- 输出四步全部结果：单闸通过率 / 漏斗 / 留一法 / Jaccard / 候选质量对比。

### 编写 gate config 的要点

```python
# 每道闸一个 (标签, 函数) 元组；函数返回 True 表示通过
# 注意：只放"硬闸"。分段复核通道不要建成硬闸，
#      否则会高估漏损（见判读规则 5）。
GATES = [
    ("G1 便宜 PB<=1.6 且三年分位<=50%", lambda r: ok(r['pb'], None, 1.6) and ok(r['pbq'], None, .50)),
    ("G2 盈利 ROE>=4%",              lambda r: ok(r['roe'], .04)),
    ...
]
# 终局口径闸（通常是"股息带/收益率带"这类最终区间），单独指定
FINAL = ("6.1 默认带 4%~6%", lambda r: ok(r['div'], .04, .06))
# 用于候选质量对比的列
QUALITY_COLS = [('pb','PB中位'), ('pbq','PB分位中位'), ('roe','ROE中位'),
                ('debt','负债率中位'), ('div','股息率中位')]
```

## 输出要求

- 每一步都要给**原始数字**，不要只给百分比。
- 留一法必须包含"− 某闸 → +N 只（+X%）"的完整表，包括 +0 的行。
- Jaccard 矩阵里全通闸那一行要显式标注"退化为其它闸通过率"。
- 候选质量对比必须给中位数，并明确指出**代价方向**。
- **结论必须区分"能改什么"的权限层级**：
  - 改定义 / 记录项 / 评估方法 → 通常无需改动策略参数
  - 改阈值 / 增删闸 / 改结合方式 → 属参数变更，须走该策略自己的修订流程
  - **如果策略章程自己有"禁止因个别候选被淘汰而回调参数"这类条款，必须显式指出：**
    "为扩大候选而放宽阈值"是被堵死的路径，但"更换结合机制（AND→合成得分）"不等同于回调参数。

## 常见陷阱

1. **把分段复核通道当硬闸建模** → 高估漏损，得出"设计有问题"的错误结论。先读原章程有没有复核条款。
2. **基数含表头行** → 百分比整体偏移。务必跳过首行。
3. **用简化版闸定义跑第一遍就下结论** → 复杂闸（如"带 + 上限复核 + 下限观察池"三档结构）必须先按原文拆清再建模。
4. **只看通过率不看留一法** → 通过率高的闸不代表不卡人（取决于它在漏斗中的位置）。留一法才是边际约束力。
5. **把 Jaccard=1.00 直接解释为"完全冗余"** → 若双方都是全通闸，1.00 是退化值。
6. **引用源方法论 PDF 的表格数字前，必须用表格结构解析而非文本层抽取**。
   文本层抽取会因合并单元格/空单元格造成**整行列错位**：空格子被跳过、后续数值左移一格。
   **做法**：用 `pdfplumber` 的 `extract_tables()` 取表格对象；
   抽取后逐行核对列数与表头是否一致，列数不符即为错位信号。
