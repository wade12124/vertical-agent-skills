# 周期性数据跟踪研报

## Overview

把"周期性研报自动化"从一份靠对话上下文的提示词，变成可交接的输出契约：题面自带变量清单、来源优先级、命名与落盘规则、硬红线、阈值表与闭环段。

## 何时使用

- 用户要建"每周五/每日/每月自动跟踪 X 并出报告"的定时任务。
- 用户要把已有云端自动化改成落到本地目录的文件产物。
- 用户给了一串跟踪变量 + 触发阈值，要求生成规范研报。
- 审查已有题面是否可交接（是否引用了创建会话才有的信息）。

## 输出契约（题面必须显式写明的 10 条）

逐条写进题面正文，不要依赖"上次那份"或对话历史：

1. **自包含**：变量清单、阈值、目录、命名全部内联。禁止出现"参考我们前面讨论的口径"。
2. **交付目录与命名**：绝对路径 + `{{标的}}_{{主题}}_YYYYMMDD.md`。产物落盘位置是本地还是云端对话，必须在建任务前讲清。
3. **数据源优先级与降级路径**：首选工具（如 `data_search_tool`）→ 不可用时降级为联网搜索；报告需标注该值实际来自哪条通道。
4. **每值带来源与实际截止日期**：日期指数据自身截止日，不是任务运行日。二者不等时以数据日为准。
5. **硬红线**：查不到写"本期未获取到数据"，禁止编造、禁止用估算值冒充实测、禁止沿用上期数字冒充本期。
6. **休市/长假基准**：以最近交易日为基准，并显式说明本期处于休市/假期。
7. **报告前部固定阈值检查表**：四列——阈值 / 当前值 / 是否触发 / 距阈值百分比。任一触发项在正文加粗标注。
8. **末尾固定两段**：下周关注清单 + 本期数据缺口清单。缺口清单是下期输入，不可省略。
9. **环比闭环（本地执行时）**：运行前先 Glob 同目录最近一期产物并 Read，逐项对比；必须逐条回应上期的关注清单与缺口清单（已补齐/仍缺失）。
10. **建完任务后的校验**：list 确认任务 ID、cron、时区、执行目录、model 回显；检测同排程/同目录是否已有重叠任务，有则先报告再决定。

## 风险与边界（建任务前必须告知用户）

- **云端任务 agent 侧不可运维**：创建后只返回 ID，无法从工具侧 run / update / remove / disable；停用与删除只能用户在 Automations 面板手动做。要文件产物就直接建本地任务，不要先建云端再迁移。
- **无人值守权限**：本地定时任务默认可能是 Full Access（自动搜网 + 直接写盘不问）。收紧与否要问一句。同时提示：产物目录若在主仓内，会持续产生 untracked 文件，必要时写进 `.git/info/exclude`。
- **并发双跑**：多窗口可能各自建了同名任务，同一时点各跑一次、各写一份。建之前先 list 查重。

## 工作流

1. 收齐要素：标的、周期、变量清单、阈值、交付目录、命名模式、首选数据工具。缺项就问，不要臆造默认值。
2. 用下方模板填充题面，逐条核对上面 10 条契约是否都在文本里（不是靠口头补充）。
3. list 查重 → 创建任务 → list 回读校验 → 需要时发起一次手动运行验证产出。
4. 产出到手后按契约逐条验收：缺来源、缺截止日期、缺口清单为空、阈值表列不全，都算不合格，改题面而不是改产物。

## 题面模板（占位符填充后即为自包含题面）

```markdown
对 {{标的}}（{{代码}}）的 {{主题}} 做{{周期}}跟踪，生成中文 {{周期}} 报告，
落盘到 {{绝对目录}}，文件名 {{标的}}_{{主题}}_YYYYMMDD.md。

【核心变量】
①{{变量1：结构/存量类，写清判据与关注动作}}
②{{变量2：逐家/逐项点名跟踪，列出具体对象与量级}}
③{{变量3：政策/规则类，列出具体发布方与外溢方向}}

【补充跟踪项】
④{{价格与库存}}；⑤{{成本端分项}}；⑥{{标的自身：股价/估值/子公司/出口价}}；
⑦{{现货价/开工率/库存族}}；⑧{{上游资源国政策}}。

【触发阈值】出现以下情况重点标注：{{阈值1 价格下沿}}、{{阈值2 价格上沿}}、
{{阈值3 新增停产}}、{{阈值4 规模性关停量级}}、{{阈值5 政策落地}}。

【执行要求】
1. 数据源：优先 {{首选工具}}；不可用时改用联网搜索，并在该值后标注实际通道。
2. 每个数值标注来源与实际截止日期（数据截止日，非本次运行日）。
3. 查不到的项写"本期未获取到数据"，严禁编造或沿用上期数字。
4. 遇休市/长假：以最近交易日为基准，并说明本期处于休市。
5. 报告开头先出阈值检查表，列固定为：阈值 / 当前值 / 是否触发 / 距阈值百分比。
6. 先 Glob {{绝对目录}} 找到最近一期 {{标的}} 报告并 Read，逐项做环比；
   并逐条回应上一期"下期关注清单"与"数据缺口清单"（已补齐 / 仍缺失）。
7. 正文之后给出对 {{标的}} {{主线A}} 与 {{主线B}} 盈利影响的简要判断。
8. 末尾固定两段：下期关注清单、本期数据缺口清单。

【结构】一句话结论 → 阈值检查表 → 核心变量分节 → 补充项分节 → 盈利影响判断
→ 下期关注清单 → 数据缺口清单
```

## 验收 checklist

- [ ] 题面零上下文依赖（把这份文本单独发给一个全新会话，能直接执行）
- [ ] 命名与目录为绝对路径且含 YYYYMMDD
- [ ] 数据源优先级 + 降级路径 + 实际通道标注都在
- [ ] "未获取到数据"红线在文内
- [ ] 休市基准在文内
- [ ] 阈值表四列定义在文内
- [ ] 关注清单 + 缺口清单在文内
- [ ] 环比（Glob 最近一期 + 回应上期缺口）在文内
- [ ] 任务已 list 回读校验，无重叠任务
